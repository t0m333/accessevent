# Оценка ИС AccessEvent

## SWOT-анализ

|  | Плюсы | Минусы |
|---|---|---|
| **Внутреннее** | **Силы:** инклюзивность на уровне архитектуры (визуальные уведомления, сурдоперевод, фильтр); автоматические тесты в CI; адаптивная вёрстка; JWT-аутентификация | **Слабости:** нет push-уведомлений; тесты идут на SQLite, а продакшен на PostgreSQL; нет пагинации списка мероприятий; нет роли модератора для чата |
| **Внешнее** | **Возможности:** рост аудитории за счёт инклюзивности; интеграция с календарями и соцсетями; субсидии на доступные сервисы; партнёрство с НКО | **Угрозы:** конкуренты с мобильными приложениями; изменение требований доступности (обновления WCAG); утечка персональных данных; зависимость от одного хостинга |

## Вывод о готовности к опытной эксплуатации

Система готова к опытной эксплуатации в ограниченном контуре: основные функции (регистрация, вход, создание мероприятий, регистрация на мероприятие, личный кабинет, визуальные уведомления) реализованы и покрыты автоматическими тестами. Развёртывание автоматизировано через GitHub Actions и CI.

Перед публичным запуском требуется:
- аудит безопасности (проверка JWT, rate limiting на регистрацию и вход);
- нагрузочное тестирование (проверить работу при 1000+ одновременных пользователей);
- переход тестов на PostgreSQL для проверки реальных CHECK-ограничений;
- резервное копирование с настроенным расписанием и проверкой восстановления.

## Направления модернизации

### 1. Push-уведомления о старте мероприятия

**Что:** браузерные push-уведомления (Web Push API).
**Зачем:** напоминание о мероприятии без открытой вкладки.
**Технологии:** Service Worker, VAPID-ключи, Flask + pywebpush.
**Для слабослышащих:** визуальные push вместо звуковых напоминаний — критично для целевой аудитории.

### 2. Интеграция с календарём

**Что:** кнопка «Добавить в календарь» (iCal / Google Calendar).
**Зачем:** не пропустить начало мероприятия.
**Технологии:** генерация .ics-файла на сервере через библиотеку icalendar; Google Calendar API.
**Для слабослышащих:** не полагаться на аудио-сигналы, а видеть событие в своём календаре.

### 3. Автоматические субтитры для видеоматериалов

**Что:** перевод речи ведущего в субтитры через ИИ.
**Зачем:** доступ к содержанию трансляций без слуха.
**Технологии:** OpenAI Whisper (локально) или облачные API распознавания речи (Google Speech-to-Text, Yandex SpeechKit).
**Для слабослышащих:** прямой доступ к содержанию — основная ценность для целевой аудитории.

### 4. Мобильное приложение (PWA)

**Что:** Progressive Web App, устанавливается как приложение.
**Зачем:** удобный доступ с телефона, работа офлайн-кеша.
**Технологии:** Service Worker, Web App Manifest, офлайн-кеш шаблонов.
**Для слабослышащих:** уведомления и чат доступны с телефона без браузера, всегда под рукой.

### 5. Расширенная модерация и роли

**Что:** роль «модератор» с правами на удаление комментариев, блокировку пользователей, жалобы.
**Зачем:** безопасность платформы, борьба со спамом и оскорблениями.
**Технологии:** расширение модели User, отдельный blueprint `/api/moderation`.
